## 0. 결정 요약

| 결정 사항 | 선택 | 근거 |
|---|---|---|
| 대원칙 | **로직/렌더 분리** — 시뮬레이션은 순수 Dart, Flame은 재생만 | 헤드리스 대량 검증, 단위 테스트, AI 에이전트 개발 루프 |
| 경영 파트 이동 | 태스크 주도 FSM + A* + 셀 트윈 | 장르 표준, 구현 단순 |
| 경기 파트 구동 | **창발 코어 (b)** — 역할 스티어링 + 근접 트리거 판정 | "진짜 농구하는 느낌" 최우선 + 감독 개입 게임플레이가 공짜로 성립 |
| 창발의 부작용 통제 | 디렉터 가드레일 4종 (처음부터 내장) | 스틸 스팸·교착·뭉침·페이스 통제 불가 방지 |
| 세트 플레이 | 대본(이벤트 로그) 방식을 "작전 카드"로 국소 재활용하는 하이브리드 | 창발 코어의 탈출구 겸 코치 콘텐츠 |
| 재현성 | 고정 틱 + 시드 RNG + 이산적 개입 창 | 리플레이·테스트·밸런스 하네스의 전제 |

### 검토했던 대안: (a) 이벤트 로그 방식
포제션 결과를 대본으로 먼저 확정하고 화면이 재생만 하는 방식. 밸런스 튜닝이 쉽고(수치와 움직임 분리) Football Manager식 정석이지만, 다음 이유로 **경기 코어로는 기각**:
- "진짜 캐릭터들이 농구하는 느낌"을 내려면 결과 조건화 샘플링(성공이면 수비를 늦게 도착시키는 트릭) 등 연출 보정이 지저분해짐
- 감독 지시의 즉각 반영(지시 → 움직임이 눈에 보이게 변함)이 구조적으로 약함
- 단, 판정 수식(§3-4)과 대본 기계는 세트 플레이(§5-3)로 재활용

### (b) 창발 방식의 비용 (감수 항목)
**스티어링 파라미터가 곧 게임 밸런스**가 된다 — 수비 이동속도 5% 변경이 리그 턴오버율과 승률 곡선을 바꾼다. 움직임과 밸런스를 따로 튜닝할 수 없으므로 튜닝 반복 횟수가 많다. → 대량 시뮬 하네스(§7)를 1급 시민으로 두고 AI 에이전트에게 튜닝 루프를 맡기는 것으로 상쇄.

## 1. 전체 아키텍처

```
[순수 Dart 시뮬레이션 코어]  ← 렌더링 미의존, 고정 틱, 시드 RNG
 ├─ 경영 시뮬: 태스크 FSM, 능력치·재정·훈련
 ├─ 경기 시뮬: 창발 코어 + 디렉터 + 판정기
 └─ 출력: 틱 스트림(좌표·볼 상태) + 이벤트(득점·스틸·하이라이트)
        ↓
[Flame 연출 층]  ← 틱 스트림 소비, 결과에 영향 없음
 ├─ 아이소메트릭 투영 + z축 오프셋(슛 궤적) + 그림자
 ├─ 스프라이트 애니메이션(4방향), 트윈, 주스(이펙트·말풍선·함성)
 └─ 카메라·배속(재생기 시간 배율)
        ↓
[Flutter 위젯 UI]  ← 메뉴·스탯·작전판·타임아웃 다이얼로그
```

시뮬레이션 코어는 Flame을 import하지 않는다. 이 분리가 헤드리스 5,000경기 밸런스 검증(§7)과 `flutter test` 기반 AI 에이전트 루프의 전제다.

## 2. 경영 파트: 시설 내 캐릭터 이동

시뮬레이션 게임 캐릭터 움직임의 표준 3층 구조:

```
[시뮬레이션 층] 틱 단위 결정 — "선수 A가 셀 (3,5)의 훈련기구로 이동해 훈련"
[이동 층]       A* 경로 탐색 → 셀 목록. 논리 위치는 항상 격자 셀
[연출 층]       셀→셀 스프라이트 보간(셀당 ~0.3초) + 걷기 애니메이션
```

캐릭터별 유한 상태 기계(FSM):

```
대기(Idle) → 태스크 선택 → 이동(WalkTo) → 행동 수행(Act) → 대기 ...
```

- **태스크 선택**: 우선순위 목록으로 충분 (스케줄 > 필요도 > 어슬렁). 유틸리티 AI 불필요
- **행동 수행**: 행동 애니메이션 + 수치 변경 + 이펙트(카이로소프트식 "숫자 뿅뿅")
- 수십 명이 각자 FSM을 돌면 경영 화면의 생동감은 자동으로 나온다

## 3. 경기 파트: 창발 시뮬레이션 코어

### 3-1. 틱 구조

- 초당 8~10틱. 각 틱에 선수 10명의 지시(directive) 평가 → 스티어링 이동 → 근접 트리거 판정
- 출력: `TickState { positions: Map<PlayerId, Vector2>, ball: BallState }` — 좌표는 코트 바닥 기준, z(높이)는 연출 층에서 포물선 파라미터로 처리

### 3-2. 포제션 상태 기계 (팀 단위)

```
공격 셋업 ⇄ 속공(전환) ⇄ 수비 전환
```

턴오버·리바운드 발생 시 양팀 역할이 즉시 반전 → 속공 흐름은 규칙에서 자연 창발.

### 3-3. 역할 스티어링 (선수 단위, 매 틱)

| 역할 | 규칙 (한 줄 수준) |
|---|---|
| 볼 핸들러 | 목표 지점으로 드리블 전진, 슛 효용 평가(§4-2), 압박 시 패스 판단 |
| 오프볼 공격수 | 포제션 상태별 스페이싱 앵커로 arrive + 동료 분리 벡터 + 쿨다운마다 컷/스크린 |
| 수비수(맨투맨) | `마크 대상↔골대 선분 위의 점`으로 이동. 반응 지연 ∝ 1/수비 능력치 |
| 수비수(지역) | 구역 앵커 기준으로 규칙 교체 (감독 지시로 스왑, §5) |

"수비 좋은 선수가 잘 따라붙는다"는 반응 지연 항에서 공짜로 표현된다.

### 3-4. 판정 수식 (스틸·슛 공통 구조)

판정 트리거는 공간 근접·상태에서 발생하고, 수식은 로지스틱 하나로 통일:

```dart
double actionProb(double atkStat, double defStat, Context ctx) {
  final diff = atkStat - defStat * w + ctx.modifiers; // 피로, 사기, 오픈 정도...
  return clamp(baseRate[ctx.type] * sigmoid(diff / slope), 0.05, 0.95);
}
```

- **`slope`가 밸런스의 심장**: 가파르면 능력치가 절대적(육성 보람↑, 이변↓). 타이쿤은 "내가 키운 능력치가 눈에 보이게 결과를 바꾼다"가 생명이므로 가파른 쪽에서 시작해 튜닝
- **클램프 5~95% 필수** — 확률 0/100%는 게임을 계산기로 만든다
- 예: 스틸 = `sigmoid((수비.스틸 − 공격.핸들링)/slope)`, 슛 = 존별 baseRate × 슈터·수비수·상황 보정
- 스틸 성공 → 즉시 포제션 반전(§3-2) → 속공

### 3-5. 재현성 규율

- **시드 고정 RNG**: 경기당 시드 하나로 모든 추첨. 같은 시드 = 같은 경기 → 리플레이 공짜, `flutter test`에서 "시드 42로 A팀 승리" 단정 가능
- 감독 개입(§5)은 이산적 입력 로그로 기록 → 시드 + 입력 로그 = 완전 재현

## 4. 디렉터 가드레일 (창발의 퇴행 방지 — 처음부터 내장)

| # | 퇴행 패턴 | 가드레일 | 조절 손잡이 |
|---|---|---|---|
| 1 | 스틸 스팸 (근접마다 판정 → 턴오버 폭발) | 수비수별 스틸 시도 쿨다운 + 실패 시 확률적 리치인 파울 | 쿨다운·파울률 = 경기당 스틸 수(현실 농구 팀당 7~9개) |
| 2 | 슛을 안 쏨 (무한 패스 교착) | 슛 결정을 효용 함수로: `오픈 정도 + 슛 능력치 + 성향 − 거리 페널티 + 샷클락 절박도` | 절박도 항이 커지면 교착이 구조적으로 불가능 |
| 3 | 뭉침 (유아 축구 현상) | 동료 간 분리 벡터 + 포제션 상태별 스페이싱 앵커 | 앵커 배치 = 포메이션 데이터 |
| 4 | 페이스 통제 불가 | **전역 템포 계수 1개** (이동 속도·판정 빈도에 곱) — 처음부터 설계에 포함, 나중에 넣으면 전부 재튜닝 | 경기 템포·점수대 직접 조절 |

## 5. 감독 개입 층 (핵심 게임플레이)

창발 코어에서 선수 행동은 전부 파라미터로 구동되므로, **감독 지시 = 파라미터의 런타임 변경**. 새 시스템이 아니라 기존 손잡이에 UI를 다는 것.

### 5-1. 지시 → 파라미터 매핑

| 감독 지시 | 내부 변경 |
|---|---|
| 빠른 농구 / 지공 | 전역 템포 계수 + 샷클락 효용 절박도 항 |
| 3점 위주 / 골밑 공략 | 슛 존 성향 가중치 |
| 에이스에게 몰아줘 | 패스 대상 선정 가중치 |
| 맨투맨 ⇄ 지역방어 | 수비수 지시 규칙 교체 (마크 기준 ⇄ 구역 앵커 기준) |
| 풀코트 프레스 | 수비 압박 거리 + 스틸 쿨다운 단축 |
| 에이스 더블팀 | 특정 공격수에 마커 2명 배정 |
| 선수 교체 | 스태미나·능력치 다른 개체로 스왑 |

**두 채널 동시 반영이 원칙**: 움직임이 즉시 눈에 보이게 바뀌고(프레스 → 수비수들이 실제로 따라붙음) + 판정 확률도 실제로 바뀜. "내 지시 → 화면이 변함 → 결과가 변함"의 끊김 없는 연결이 감독 판타지의 핵심.

### 5-2. 타임아웃

- 시뮬레이션 일시정지 + 지시 변경 창 + 부가 효과(스태미나 소폭 회복, 상대 모멘텀 보정치 리셋)
- 경기당 횟수 제한 → "언제 쓰느냐"가 전략 자원

### 5-3. 세트 플레이 = 대본 기계의 국소 재활용 (하이브리드)

- (a)방식의 포제션 대본(`PossessionScript { beats: [Beat{t, actor, action, spot}] }`)을 **작전 카드**로 사용
- 타임아웃 직후 첫 포제션의 처음 몇 초만 대본(픽앤롤·아이솔레이션·모션 오펜스 등 3~5종)이 선수 지시를 오버라이드 → 이후 창발 모드 복귀
- 작전 카드는 수집·성장 요소(코치 스킬 트리)로 확장 가능
- 판정 로직을 트리거와 분리해 두면, 느낌이 너무 산만할 경우 대본 비중을 늘리는 후퇴 경로도 확보됨

### 5-4. 설계 원칙

1. **모든 지시에 트레이드오프**: 프레스 = 스틸↑ / 파울·스태미나↓, 빠른 농구 = 포제션↑ / 야투율↓. 트레이드오프 없으면 정답 지시 하나만 남아 전략이 죽는다
2. **대칭 설계**: 상대 AI 감독도 같은 지시 시스템 사용 → 가위바위보 깊이 + 상대 감독 성향 스카우팅 콘텐츠가 공짜
3. **개입 예산**: 실시간 상시 지시보다 **이산적 개입 창**(타임아웃·쿼터 브레이크) 권장 — 카이로소프트류 관전 템포 유지 + 입력 로그 재현성(§3-5) 유지

## 6. 연출 층 (Flame)

- 셀/좌표 이동: `MoveToEffect`/`MoveAlongPathEffect` 또는 `update(dt)` lerp
- 걷기: `SpriteAnimationComponent` + 아이소메트릭 4방향(대각) 시트, 이동 벡터로 방향 선택
- 슛 궤적: 이벤트 파라미터(시작점·성공 여부)를 받아 z 투영 포물선 + 그림자 ([타당성 문서 §3](./2026-09-02_flame-isometric-basketball-tycoon.md) 참조)
- 깊이 정렬: 바닥 기준 `block.x + block.y` (Heeve 패턴)
- 배속: 재생기 시간 배율 하나로 처리
- **주스가 "느낌"의 절반**: 캐릭터 AI보다 먼저 투자할 것 — 리액션 말풍선, 관중 함성, 득점 화면 흔들림·파티클, 하이라이트 컷인(하이라이트 플래그 이벤트가 트리거), 경기 템포 완급. 같은 좌표 데이터도 주스가 있으면 "진짜 경기", 없으면 "좌표 이동"으로 보인다

## 7. 검증·밸런스 하네스 (1급 시민)

### 7-1. 헤드리스 대량 시뮬레이션 (CI 포함)
파라미터 변경 시마다 렌더링 없이 5,000경기 자동 실행 → 리포트:
- 평균 득점(농구다운 80~120점대인가), 포제션 수, 경기당 스틸/턴오버/파울 수
- **능력치 탄력성**: 능력치 +10의 승률 변화량 (타이쿤 육성 보람의 정량 지표)
- 특정 감독 지시의 승률 효과 크기 (±15%p급이면 너프 대상)

### 7-2. 테스트 목록
- 속성 테스트: 모든 틱에서 선수가 코트 안 / 볼 소유자 ≤ 1명 / 세트 플레이 중 배역 선수는 비트 시각 ±0.2초 내 도착
- 골든 테스트: 특정 시드 경기의 틱 스트림 고정 (`flame_test` 골든은 렌더 검증용으로 별도)
- 회귀 방지: 연출 층 수정이 경기 결과를 바꾸지 않음을 시드 재현으로 검증

### 7-3. AI 에이전트 튜닝 루프
판정 확률·성향·포메이션 앵커를 **코드가 아닌 데이터 테이블**에 두어, AI 에이전트가 "테이블 수정 → 대량 시뮬 → 리포트 확인" 루프를 자율 반복할 수 있게 한다.

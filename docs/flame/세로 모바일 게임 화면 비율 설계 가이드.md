# 세로 모바일 게임 화면 비율 설계 가이드

세로 풀스크린 게임(예: 벽돌깨기)에서 **기기 비율 차이로 생기는 유불리를 없애기 위한** 화면/플레이필드 설계 정리.

## 1. 문제 정의

- 요즘 폰들은 비율이 제각각 (9:16 ~ 9:21), 태블릿은 4:3.
- 화면을 그냥 꽉 채우면 **세로로 긴 폰일수록 플레이 영역이 넓어져 유리/불리** 발생.
- 벽돌깨기처럼 **플레이 영역 크기가 곧 난이도**인 게임은 비율을 고정해야 공평함.

## 2. 핵심 원칙: 보드(플레이필드)는 비율을 고정한다

- **게임성에 영향을 주는 영역(공이 튕기는 보드)** = 비율 **고정**.
- **나머지 공간** = 점수/UI/배경/광고로 채우거나 레터박스.
- 이렇게 하면 21:9 긴 폰이든 4:3 태블릿이든 **물리적으로 동일한 난이도**.

```
21:9 긴 폰                      9:16 짧은 폰
┌─────────────┐                ┌─────────────┐
│▓▓ 광고/점수 ▓│ ← 남는 공간     │  점수 100   │
├─────────────┤                ├─────────────┤
│ ▒▒ 벽돌 ▒▒ │   ← 모든 기기    │ ▒▒ 벽돌 ▒▒ │
│            │     동일한       │            │
│     ●       │     보드 비율    │     ●       │
│   ▬▬▬▬      │                │   ▬▬▬▬      │
├─────────────┤                └─────────────┘
│▓▓ 남는 공간 ▓│
└─────────────┘
```

## 3. 추천 보드 비율: 9:16 (= 1:1.78)

| 비율 | 특징 | 판단 |
|------|------|------|
| **9:16 (1:1.78)** | 거의 모든 폰보다 약간 짧음 | ✅ 가로가 항상 꽉 차고, 위아래 여백만 생김 |
| 9:18 (1:2.0) | 중간 길이 폰 기준 | △ 짧은 폰에서 좌우 잘림/축소 |
| 9:19.5 (1:2.16) | 아이폰 기준 | ❌ 너무 길어 짧은 폰·태블릿에서 좌우 여백·축소 |

**원칙: 보드 비율은 "가장 안 길쭉한(짧은) 타겟 기기보다 짧게"** 잡아야 가로가 항상 꽉 차고, 비율 차이가 세로 여백으로만 흡수됨.

- 보드 비율: **9:16** (안전), 덜 답답하게 하려면 9:17.
- 기준 디자인 해상도: **1080 × 1920**.

## 4. 표시 크기 계산 메커니즘

```
표시 크기 = min( 화면너비 / 보드너비 , 화면높이 / 보드높이 )
```

- 폰은 세로로 길어서 **항상 가로(너비)가 제약 조건** → 가로 100% 채우고 세로 여백.
- 보드를 9:16보다 길게 잡으면 짧은 폰에서 세로가 먼저 차서 **가로에 여백**이 생김(원치 않음).

## 5. 가로 맥스 캡 (태블릿 대응)

태블릿(4:3, W/H=0.75)은 보드(9:16, W/H=0.5625)보다 **가로가 넓어서**, 가로 100%로 채우면 보드가 거대해지고 세로가 넘침 → **가로 맥스 캡 필요**.

세로 모드 기기별 가로/세로 비율(W/H):

| 기기 | 세로 비율 | W/H |
|------|-----------|-----|
| 긴 폰 | 9:21 | 0.43 |
| 보통 폰 | 9:19.5 | 0.46 |
| 짧은 폰 | 9:18 | 0.50 |
| **보드 9:16** | 9:16 | **0.5625** |
| iPad (4:3) | 3:4 | **0.75** ← 보드보다 넓음 |

→ 폰은 전부 0.5625 미만이라 캡이 안 걸리고, **태블릿만 캡에 걸림**.

### 권장 공식 (자동 캡 — 별도 매직넘버 불필요)

```
// 1. 가로 채우되, 화면 높이도 넘지 않게 (이 한 줄이 사실상 캡 역할)
보드너비 = min(화면너비, 화면높이 × 9/16)

// 2. (선택) 절대 상한 — 폴더블·초대형 태블릿 방어
보드너비 = min(보드너비, 1200)   // 디자인 단위 기준

보드높이 = 보드너비 × 16/9
```

- **폰**: `화면너비`가 작아 선택 → 가로 100%.
- **태블릿**: `화면높이 × 9/16`이 작아 선택 → 세로 fit + 가로 레터박스.

### 캡 전략 비교

| 전략 | 캡 값 | 언제 |
|------|-------|------|
| **자동 (권장)** | `화면높이 × 9/16` | 거의 모든 경우 — 별도 상수 불필요 |
| + 절대 상한 | `min(위 값, 1080~1200)` | 폴더블·초대형 기기 방어 |
| 물리 크기 | 보드 폭 ≤ 7~8cm 환산 | 조작성(손 도달)이 중요할 때 |

## 6. 엔진별 비율 고정 / 레터박스 방법

| 엔진 | 방법 |
|------|------|
| **Unity** | `CanvasScaler` → `Scale With Screen Size` + `Match` 조절, 또는 카메라 `orthographicSize`를 종횡비로 보정 |
| **Godot** | Project Settings → `Stretch Mode: canvas_items` + `Aspect: keep` (자동 레터박스) |
| **Cocos** | `ResolutionPolicy.SHOW_ALL` (비율 유지 + 레터박스) |

> Godot의 `Aspect: keep`, Cocos의 `SHOW_ALL`은 자동으로 비율 고정 + 레터박싱을 해줘 가장 쉽게 해결.

## 7. 추가 처리

- **Safe Area**: 노치·홈 인디케이터 피해서 상단/하단 UI 배치.
- **여백 활용**: 위 = 점수/메뉴, 아래 = 일시정지/여유, 또는 배경 확장.
- **패들 이동·공 속도**: 보드를 정규화 좌표(0~1)로 계산 후 픽셀 변환 → 비율 같으면 체감 동일.

## 요약

1. 게임성에 영향 주는 **보드는 9:16으로 비율 고정**.
2. `보드너비 = min(화면너비, 화면높이 × 9/16)` → 폰은 가로 꽉, 태블릿은 자동 레터박스.
3. 필요 시 절대 상한(1080~1200)으로 극단 기기 방어.
4. 남는 공간은 UI/배경, Safe Area 대응.
